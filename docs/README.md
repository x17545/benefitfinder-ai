# 문서 지도

문서를 찾는 첫 진입점이다. 같은 결정을 여러 파일에 복제하지 않고, 아래 표에서 정한 기준 문서를 갱신한다. 링크된 문서의 버전은 본문에서 관리하며 현행 파일명에는 버전 번호를 붙이지 않는다.

[HTML 문서 지도](document-map.html)에서는 가상 공고 세 건이 수집·검수·계산을 거쳐 추천으로 이어지는 과정을 한 단계씩 넘겨 보거나 재생할 수 있다. 아래의 흐름도에서 각 단계의 원래 문서를 열 수 있다. 파일을 내려받아 브라우저에서 열면 문서 링크는 GitHub의 `main`으로 이동한다. 제품을 처음 읽는다면 [README의 프로젝트 흐름](../README.md#프로젝트-흐름-한눈에-보기)부터 본다.

초기 운영 데이터 적재는 모델 검수 없는 [source-only 배치](development/DECIDER_PIPELINE.md#모델-검수-없는-초기-원천-적재)로 진행했다.

이 배치의 AI 호출·실패는 0건이다. 금액 미확인 항목과 계산 가능한 원공고 기반 항목은

### 화면과 정책 계산

- **사용 흐름:** S1에서 시작해 13단계 조건을 고르면 분석 진행·오류를 거쳐 S3 조합과 보완 목록을 확인한다. S4는 네 가지 상황 변화를 다시 계산하고, S5는 상세·진단을, S6는 가상 서비스를 보여 준다. 화면은 라우팅·중첩 응답 검증을 적용하고, 개발용 404 예시와 서버 가상 결과를 구분한다. 서버 가상 결과는 화면과 저장 이미지에 명시한다.
- **추천·상세:** [API 안내](../backend/src/benefitfinder/api/README.md)에 추천·상황 변화·상세 경로, 공통 오류·OpenAPI가 있다. 게시 현금 정책은 후보·자격·기간별 조합·상세·상황 변화를 계산하며, 정확한 그래프 탐색·동률 정렬·자원 한도·보완 목록을 지원한다. F14는 게시 카탈로그에서 서비스와 단가를 읽을 수 있다. 단가 근거가 없으면 금액 없이 표시하고 환산액은 현금 조합과 분리한다.
- **공식 지역:** [`GET /api/v1/options`](../backend/README.md#실제-지역-선택-api)는 현행 법정동코드에서 자치 시군구를 제공한다. 조회 실패 시 가상 지역으로 대체하지 않고 빈 목록·실패·재시도를 표시한다. 분석 실패 후 예제 결과 버튼은 개발 모드에서만 보인다.
- **기억하기·삭제:** 탭 안 입력·결과·기억하기 선택을 복원하고 조건 변경이나 캐시 손상 시 결과를 지운다. 선택한 조건은 분석 시작 시 브라우저에 저장하고 30일 후 다음 접속에서 삭제한다. 전체 삭제와 조합 PNG 저장을 제공한다. P1·P2와 조건 입력 8·9·12단계에 서버 무저장, 탭 임시 보관, AI 설명의 전달 범위와 통계가 켜진 환경에서 전송하는 이벤트의 범위를 안내한다.
- **만기형 지원금:** 검수한 적립·지급 일정을 바탕으로 기간 내 현금 수령 예정액과 예상 적립액을 구분한다. 현재가치는 선택 기간 안에 받는 현금만 할인한다.
- 웹의 상황 변화 요청은 개발 StrictMode의 효과 재실행과 전송 전 화면 이동·상황 변경에서 예약을 취소해 중복 POST를 막는다. 이미 전송된 요청의 서버 차감을 되돌리지는 않는다. [요청·취소와 회귀 검증](../apps/web/README.md#상황-변화-요청과-취소)을 따른다.
- [정책 상세의 신청 안내](../apps/web/README.md#s5-신청-안내와-원문)는 현금·서비스 게시 입력의 `application_guide`를 API에서 화면까지 연결한다. 신청 방법·접수 기관·서류는 같은 버전의 검수된 원문 인용으로 저장하며 원문·전체 승인 해시를 검증한다. 안내 미확인과 검수한 원문에 안내가 없는 경우를 구분하고 운영 기관으로 접수 기관을 추정하지 않는다. 안내 없는 기존 입력·승인 해시는 유지한다. 실제 신청 안내 자료의 사람 검수는 별도다.
- 모집 상태는 현금·서비스의 추천·상세에서 오늘의 KST 날짜로 계산한다. 저장된 모집 예정 상태는 확인한 시작일이 되면 모집 중으로 전환하며 명시적 종료·미확인은 임의로 모집 중으로 바꾸지 않는다. 웹의 저장 결과에서도 종료일이 지난 모집 태그와 신청 문구를 구분하고, D-n은 마감 14일 이내에 표시한다. 프론트엔드가 기존 조합·금액을 다시 계산하지 않는다.
- **후속:** 실제 정책 30개와 만기 자료, 실제 서비스와 단가 자료의 사람 검수·게시.

### 수집·검수·원문 근거

- **[F08 통합 갱신](../backend/src/benefitfinder/jobs/DAILY_REFRESH.md):** 온통청년, 설정된 보조금24·공식 문서, ECOS 금리의 실행 결과와 단일 디스코드 알림 상태를 기록한다. 중복 실행 차단과 Linux `systemd`·macOS `launchd`의 03:00 KST 설정 생성을 지원한다. 준비된 F12 분석 작업은 수집 이후에 실행할 수 있다.
- **[수집 성공본 DB 인계](../backend/src/benefitfinder/infrastructure/database/COLLECTED_POLICIES.md):** `COLLECTION_WRITE_DATABASE_URL` 설정 시 완전한 파일 생성본·변경 이력을 저장하고 API 없이 재인계할 수 있다. 미검수 원천은 게시 정책·조항과 분리한다.

### PostgreSQL과 AI 검증

- **조항 저장소:** 문서·조항·게시/검수 상태를 명시적 SQL로 마이그레이션한다. 비동기 조회에서 상태·버전을 구분하고, 같은 정책의 별도 지침은 URL·버전·해시를 분리한다. 미게시 승인 근거는 기존 행을 보존해 추가하고 지정 버전·항목만 화면에서 확인한다. 별도 PostgreSQL 17에서 읽기·쓰기·장애·화면을 검증했다.
- **현금 정책 카탈로그:** 0002 마이그레이션·승인 해시 검증·명시적 게시 CLI·읽기 전용 조회를 제공한다. PostgreSQL 17에서 가상 자료의 게시·버전 교체·롤백·권한과 추천·상세 연결을 검증했다. 0010에서 카탈로그와 F13을 같은 승인 해시로 게시하고 조회 때도 그 해시를 확인한다.
- **서비스 카탈로그:** 공식 서비스 내용과 별도 가격 근거를 전체 검수 해시에 묶어 저장한다. 같은 원천이 바뀌면 승인 해제·재검수를 적용한다. DB 모드의 추천·공개 상세·메타 조회를 지원한다. 실제 사람 검수·자료 공개와 가격 변경 자동 탐지는 후속이다.
- **실제 승인 근거:** 별도 로컬 `_test` DB에 승인 내보내기만 `draft`로 적재한다. 원본 ID·해시·검수자·사유·범위를 보존한다. #19를 결합한 검증 서버에서 실제 지역 입력부터 E4B 안내·원문 표시까지 확인했다. 자격 확인 전·금액 `null`·조합 없음 상태를 유지한다.
- **모델 실행:** 개발용 [llama.cpp](development/LOCAL_LLM.md)는 로컬 GPU에서 F12 도구 호출·문맥별 추출과 F13 설명을 같은 설정으로 연결한다. 운영은 외부 API의 HTTPS 주소·모델·키를 명시한다. 기존 Ollama는 명시적 호환 경로다. 외부 공급자 평가는 별도다.
- **Decider 검증:** 정형 우선 경로의 실제 4,029건 필드 전달 감사와 로컬 표본 검증은 [파이프라인](development/DECIDER_PIPELINE.md#정형-우선-경로-재현-검증)을 따른다. 이전 경로는 공식 model snapshot hash·source/model/question identity·private checkpoint를 유지한다. 12GB에서 v2 실제 10건은 ready 0·held 10·failed 0·published 0이었고 critical recall 37.889%로 평가 미달이다. 격리 PostgreSQL 189건은 31.366초에 통과했다. 공통 PR 검사 결과는 PR에 별도로 기록한다.

2026-11-16 공개 배포의 `GET /api/v1/meta`·`GET /api/v1/options`·`POST
/api/v1/recommendations`는 HTTP 200을 확인했다. 가상 25세·경기·구직·1년·월세 fixture의
1년 PV off 응답은
`portfolios=0`, `not_yet_reviewed=55`, `closed_now=36`, `not_eligible=6`이었고 6개 view가
같았다. 응답은 `virtual_data=false`, `ai_generated=false`였지만 실제 금액 조합 검증 완료를
뜻하지 않는다. 운영 현금 정책 97건은 모두 `reviewed=false`였고 calculator의 실행 가능한
금액 조합은 0이다. 현재 Decider 코드가 이 배포에 포함된 것은 아니다.

`/health`는 프로세스 생존 확인이다. 목표 아키텍처, 디렉터리 존재, 참조 계산 테스트 통과만으로 기능·운영 검증을 판단할 수 없다. 실제 동작과 검사 범위는 코드·테스트·[검사 안내](development/REPOSITORY_SETTINGS.md#3-현재-공통-검사의-범위)를 확인한다. 구현 상태가 바뀌면 이 절을 갱신한다.

별도로 [로컬 현금 정책 모드](../backend/README.md#로컬-현금-정책-계산)는 기본 앱에서 파일로 읽은 응시료·월세 정책의 실납부액과 시점별 중복 조건을 판정한다. 운영 게시나 운영 정책 조합에는 연결하지 않는다.
