## 작업별 읽는 순서

1. 처음 참여: [루트 README](../README.md) → [설치 안내](development/GETTING_STARTED.md) → [협업 절차](../CONTRIBUTING.md) → [Git 절차](development/GIT_WORKFLOW.md).
2. 기능 구현: `AGENTS.md` → 기능 명세의 해당 기능·화면·수락 조건 → 아키텍처 → 관련 계약 → 수정 경로의 README·하위 `AGENTS.md` → 코딩 컨벤션.
3. 데이터 수집·분석·정제: 위 공통 기준 → 정책 데이터 준비 → [ingestion](../backend/src/benefitfinder/ingestion/README.md)·[ai](../backend/src/benefitfinder/ai/README.md)·[로컬 데이터 보관](../data/README.md).
4. 검증·리뷰: 해당 기능의 수락 조건 → 공용 계약 → 협업·Git 절차 → 저장소 운영 안내의 검사 범위.

문서만 정리하는 작업도 링크된 기준과 변경 대상 경로를 확인한다. 무관한 기능 전체를 매번 읽을 필요는 없다.

**F08 로컬 갱신:** [온통청년 갱신 실행기](../backend/src/benefitfinder/jobs/README.md#f08-온통청년-갱신-한-번-실행)는 전체 수집과 파일 생성 후에만 최신본을 전환한다. 일부 일시 실패는 한 번 재시도하고, 최종 실패 시 마지막 성공본과 시각을 유지한다. 디스코드 성공·실패 알림과 KST 시간대의 macOS에서 03:00 실행할 `launchd` 설정 생성을 지원한다. 실제 API·웹훅 비밀값과 로컬 스케줄 등록은 각 실행 환경에 필요하다.

아키텍처의 구성도와 기능 명세는 목표 구조·수락 조건이다. 디렉터리가 존재하거나 참조 계산 테스트가 통과해도 해당 기능이 구현된 것은 아니다. `/health`는 프로세스 생존 확인이며 DB·데이터 준비 상태를 보장하지 않는다. 구현 상태가 바뀌면 이 표도 갱신한다. 실제 동작과 검사 범위의 근거는 코드·테스트·[검사 안내](development/REPOSITORY_SETTINGS.md#3-현재-공통-검사의-범위)에서 확인한다.

지역 목록은 공식 현행 법정동코드에서 자치 시군구 단위로 제공한다. 갱신·캐시·오류·재현 기준은 [지역 API 안내](../backend/README.md#실제-지역-선택-api)를 따른다. 개발 모드도 지역 조회 실패 시 가상 목록으로 대체하지 않으며 빈 목록·실패·재시도를 표시한다. 추천은 가상 MVP 정책 계산이며 실제 지역별 정책 조회·운영 게시·실제 정책 계산의 PostgreSQL 연결 완료를 뜻하지 않는다. 분석 실패 후 예제 결과 버튼은 개발 모드에만 있고 예제 표시를 붙인다. 이용 안내·개인정보 처리방침은 현재 구현 범위를 설명하며 운영 배포 설정의 검증을 대신하지 않는다.

## 화면 시안과 과거 기록

- [클릭 시안](prototype/index.html)은 화면 참고용이다. PNG·HTML의 과거 수치보다 현행 기능 명세가 우선하며 제품 앱은 `apps/web/`에서 구현한다.
- [과거 기록 목록](archive/README.md)은 이전 기획·ID 대응표·계산 예시를 보존한다. 에이전트의 기본 읽기 대상이나 현행 수락 기준으로 사용하지 않는다.
- 실제 경로·책임은 [웹 README](../apps/web/README.md)와 [백엔드 README](../backend/README.md)를 따른다. 모듈 README에는 해당 모듈의 책임과 인계만 적고 공통 규칙을 복제하지 않는다.

## F13 로컬 설명 코어

[로컬 설명 명령](../backend/src/benefitfinder/ai/README.md#f13-맞춤-설명-로컬-검증), [추천 API 연결](../backend/src/benefitfinder/api/README.md#f13-설명-실행), [결과 화면의 설명·원문 근거](../apps/web/README.md#f13-결과-설명과-원문-근거)를 제공한다. 정책·버전별 게시 조항 검색, 일반 판정·코드 계산값만 전달, 인용 검사, 검색을 포함한 5초 제한과 기본 문구 전환을 구현했다. `DATABASE_URL` 설정 시 [PostgreSQL 게시 조항](../backend/src/benefitfinder/infrastructure/database/README.md)을 조회한다. 검증은 실제 PostgreSQL 17·가상 취업/주거 조항·로컬 E4B 범위이며 실제 정책 자료의 게시·신청 사실 검증 완료를 뜻하지 않는다. 기본 공통 검사와 [별도 PostgreSQL 검사](../backend/integration/README.md)를 구분한다.
