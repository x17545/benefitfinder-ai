# AI 혜택 코치 (BenefitFinder AI)
## 기능 요구 명세서 v1.0

- 프로젝트: 코디세이 Final Project
- 팀 구성: 5명
- 작성일: 2026-10-26
- 제출 마감일: 2026-11-25
- 문서 상태: 초안 (팀 검토 및 확정 필요)
- 기반 문서: PROJECT_PLAN.md v1.1

---

## 1. 문서 목적

본 문서는 AI 혜택 코치의 핵심 기능과
구현 범위, 기능별 완료 기준을 정의한다.

팀원별 개발 방향을 일치시키고,
기능 통합 및 최종 평가를 위한 기준으로 활용한다.

## 2. 서비스 핵심 흐름

1. 사용자 자연어 상황 입력
2. AI를 통한 사용자 조건 추출
3. 사용자 조건 확인 및 보완
4. 공식 청년정책 데이터 검색
5. 정책별 자격 조건 진단
6. 여러 혜택을 함께 추천
7. 중복 수혜 가능성 확인 (추가 구현 검토)
8. 신청 준비사항 및 공식 출처 안내

## 3. 기능 우선순위

### 3.1 Must (필수 기능 제안)

| ID | 기능명 | 주요 내용 |
|---|---|---|
| M01 | 자연어 상황 입력 | 사용자 상황을 문장으로 입력 |
| M02 | 조건 추출 및 보완 | 본인 조건 추출·수정, 필요한 가구 정보 선택 입력 |
| M03 | RAG 정책 검색 | 공식 정책 데이터와 관련 근거 검색 |
| M04 | AI Agent | 검색 및 상세조회 도구 선택·호출 |
| M05 | 자격 진단 | 조건별 충족·미충족·추가 확인 필요 표시 |
| M06 | 혜택 포트폴리오 | 관련 정책 3~5개를 함께 추천 |
| M07 | 신청 준비 안내 | 정책 상세, 신청기간, 공식 출처 표시 |
| M08 | 서비스 배포 | 외부에서 전체 핵심 흐름 이용 가능 |

### 3.2 Should (우선 추가 기능 제안)

- 공식 근거 기반 중복 수혜 가능성 분석
- 정책 간 중복 수혜 제한 사유 표시
- 여러 혜택의 조합 추천
- 공식 지원금액 기반 제한적 금액 비교

### 3.3 Could (선택 기능 제안)

- 나이·소득 변화에 따른 혜택 절벽 분석
- Long-term Memory 기반 개인화
- 관심 정책 및 마감 알림
- 최적 혜택 조합과 총 수혜액 계산

### 3.4 개발 범위 원칙

- RAG와 AI Agent는 필수 기술로 구현한다.
- AI는 실제 신청 자격을 확정하지 않는다.
- 부모님 소득·재산은 정책상 필요한 경우에만
  선택적으로 입력받는다.
- 입력되지 않은 정보는 임의로 추정하지 않는다.
- 추천과 진단에는 확인 가능한 근거를 표시한다.
- Should와 Could는 Must 기능 완성 후 검토한다.

※ 이 문서의 우선순위는 B안 단계적 포트폴리오형을
기준으로 작성한 제안이며, 팀 검토 후 최종 확정한다.

## 4. Must 기능 상세 요구사항

### M01. 자연어 상황 입력

- 우선순위: Must
- 주 담당: 이현서 (프론트엔드)
- 협업: 김하정 (백엔드)

#### 기능 설명
사용자가 자신의 나이, 지역, 취업 상태, 고민 등을
자연어 문장으로 입력할 수 있도록 한다.

#### 입력
- 사용자 자유 입력 문장

#### 처리
1. 사용자가 입력한 문장을 수신한다.
2. 빈 입력 및 비정상적인 요청을 검사한다.
3. 백엔드에 분석 요청을 전달한다.
4. 분석 처리 중 로딩 상태를 표시한다.
5. 요청 실패 시 오류와 재시도 방법을 안내한다.

#### 출력
- 입력 문장 접수 결과
- 조건 분석 단계로 이동

#### 완료 기준
- [ ] PC와 모바일에서 문장 입력 가능
- [ ] 빈 문장 제출 방지
- [ ] 분석 요청 정상 전달
- [ ] 로딩 및 오류 상태 표시

### M02. 사용자 조건 추출 및 보완

- 우선순위: Must
- 주 담당: 탁서윤 (AI)
- 협업: 이현서 (프론트엔드), 김하정 (백엔드)

#### 기능 설명
AI가 자연어에서 사용자 조건을 추출하고,
사용자가 해당 조건을 확인하거나 수정할 수 있도록 한다.

#### 주요 추출 항목
- 나이
- 거주지역
- 취업 상태
- 주거 상태
- 관심 분야
- 본인 소득 및 가구 정보 (입력된 경우)

#### 추가 조건 입력
정책에서 필요한 경우 다음 정보를 선택적으로 요청한다.

- 부모님과의 거주 여부
- 정책에 필요한 가구 구성 정보
- 부모님 소득 관련 정보
- 부모님 재산 관련 정보

실제 요구되는 정보와 입력 방식은
해당 정책의 공식 자격 조건을 기준으로 정한다.

#### 처리
1. AI가 입력 문장에서 조건을 추출한다.
2. 추출하지 못한 값은 미입력으로 처리한다.
3. 사용자가 추출 결과를 확인하고 수정한다.
4. 정책 검색 후 필요한 추가 조건을 요청할 수 있다.
5. 수정된 조건을 다음 분석에 반영한다.

#### 출력
- 구조화된 사용자 조건
- 수정 가능한 조건 확인 화면
- 필요 시 추가 질문

#### 완료 기준
- [ ] 주요 사용자 조건 추출
- [ ] 미입력 정보를 임의로 생성하지 않음
- [ ] 사용자 조건 수정 가능
- [ ] 부모님 경제정보를 모를 때 건너뛰기 가능
- [ ] 수정된 조건이 검색과 진단에 반영됨

### M03. RAG 기반 정책 검색

- 우선순위: Must
- 주 담당: 탁서윤 (AI/RAG)
- 협업: 윤정찬 (DB), 김하정 (백엔드)

#### 기능 설명
공식 청년정책 데이터에서 사용자와 관련된 정책을
검색하고 AI 답변에 활용할 근거 자료를 제공한다.

#### 입력
- 사용자 조건
- 관심 분야
- 검색 질의

#### 처리
1. 정책 DB에서 검색 대상 정책을 조회한다.
2. 사용자 조건과 관련된 정책을 검색한다.
3. 정책 상세 설명 및 자격 조건의 근거를 검색한다.
4. 검색 결과와 공식 출처를 연결한다.
5. 관련 자료가 없으면 검색 실패 또는 미확인으로 처리한다.

#### 출력
- 관련 정책 목록
- 정책별 상세정보
- 근거 문장 및 공식 출처 URL
- 데이터 마지막 확인일

#### 완료 기준
- [ ] 실제 공식 정책 데이터 검색 가능
- [ ] 정책별 출처 URL 제공
- [ ] 답변에 활용한 근거 확인 가능
- [ ] 검색 결과가 없을 때 적절한 안내 제공
- [ ] 테스트 질의로 RAG 검색 동작 확인

### M04. AI Agent 도구 활용

- 우선순위: Must
- 주 담당: 탁서윤 (AI/RAG)
- 협업: 김하정 (백엔드), 윤정찬 (DB)

#### 기능 설명
AI Agent가 사용자의 요청을 분석하고
필요한 도구를 선택하여 정책정보를 조회한다.

#### 주요 도구

1. search_policies
   - 사용자 조건과 관심 분야에 맞는 정책 검색

2. get_policy_detail
   - 특정 정책의 상세정보와 공식 근거 조회

3. check_eligibility
   - 사용자 조건과 정책별 자격요건 비교

4. get_application_guide
   - 신청기간, 신청 방법, 준비사항 조회

#### 처리
1. AI Agent가 사용자 요청의 의도를 분석한다.
2. 필요한 도구를 선택하여 호출한다.
3. 도구 실행 결과를 확인한다.
4. 부족한 정보가 있으면 추가 확인을 안내한다.
5. 조회된 결과를 근거로 사용자 응답을 생성한다.

#### 출력
- 도구 실행 결과
- 정책 검색 및 상세정보
- 자격 진단 요청 결과
- 근거 기반 AI 설명

#### 완료 기준
- [ ] AI Agent가 실제 도구를 호출함
- [ ] 정책 검색과 상세조회 도구 실행 가능
- [ ] 도구 결과가 AI 답변에 반영됨
- [ ] 도구 실패 시 오류를 적절히 처리함
- [ ] 테스트 시 도구 호출 기록을 확인할 수 있음


---

### M05. 정책별 자격 진단 및 결과 카드

- 우선순위: Must
- 주 담당: 김하정 (백엔드)
- 협업: 윤정찬 (DB), 탁서윤 (AI), 이현서 (프론트엔드)

#### 기능 설명

사용자 조건과 정책별 자격요건을 비교하고,
판단 결과를 시각적인 카드 형태로 제공한다.

#### 입력

- 사용자 조건 (나이, 지역, 취업 상태 등)
- 필요 시 추가한 부모님 및 가구 정보
- 정책별 공식 자격 조건 및 근거

#### 처리

1. 정책 DB에서 자격 조건을 조회한다.
2. 나이, 지역 등 명확한 조건을 규칙 기반으로 비교한다.
3. 소득과 재산 조건은 공식 기준이 구조화된 경우에만 비교한다.
4. 사용자 정보가 없거나 기준이 불명확한 조건은
   '추가 확인 필요'로 분류한다.
5. 진단 결과와 판단 근거를 프론트엔드에 전달한다.
6. 프론트엔드는 정책별 자격 진단 카드를 표시한다.

#### 출력

- 조건별 진단 상태
  - 충족
  - 미충족
  - 추가 확인 필요
- 판단 근거
- 추가로 입력하거나 확인할 정보
- 정책의 공식 출처

#### 완료 기준

- [ ] 연령 및 지역 조건을 정상 비교할 수 있다.
- [ ] 미입력 정보를 충족으로 처리하지 않는다.
- [ ] 부모님 소득·재산 정보가 필요한 경우 확인 필요로 표시한다.
- [ ] 판단 근거가 없는 조건을 임의로 확정하지 않는다.
- [ ] 프론트엔드에서 진단 카드가 정상 표시된다.
- [ ] AI가 진단 결과를 임의로 변경하지 않는다.

### M06. 맞춤형 혜택 포트폴리오

- 우선순위: Must
- 주 담당: 김하정 (백엔드)
- 협업: 탁서윤 (AI), 윤정찬 (DB), 이현서 (프론트엔드)

#### 기능 설명

사용자의 관심 분야와 자격 진단 결과를 바탕으로
우선 확인할 청년 지원정책을 여러 개 추천한다.

초기 버전에서는 관련 혜택을 함께 보여주는
기본 포트폴리오를 구현한다.

모든 추천 정책이 동시에 수급 가능하다는 의미는 아니다.

#### 입력

- 사용자 조건
- 관심 분야
- 정책 검색 결과
- 정책별 자격 진단 결과

#### 처리

1. 관련된 정책 목록을 확보한다.
2. 명확한 미충족 조건이 있는 정책을 구분한다.
3. 관심 분야와 자격 진단 결과를 기준으로 우선순위를 정한다.
4. 우선 확인할 정책을 최대 5개 표시한다.
5. 정책별 추천 이유 및 추가 확인사항을 연결한다.
6. 중복 수혜 가능성은 공식 근거가 있는 경우에만
   별도 정보로 표시한다.

#### 출력

- 추천 정책 목록 (최대 5개)
- 추천 우선순위
- 정책별 추천 이유
- 조건별 자격 진단 요약
- 중복 수혜 관련 주의 문구

#### 완료 기준

- [ ] 관련 정책이 여러 개 있으면 한 번에 표시된다.
- [ ] 관련 정책이 5개 미만이면 실제 검색된 개수만 표시한다.
- [ ] 정책별 추천 이유를 확인할 수 있다.
- [ ] 명확히 미충족된 정책을 적합한 정책으로 안내하지 않는다.
- [ ] 동시 수혜 가능성을 근거 없이 확정하지 않는다.
- [ ] 검색 결과가 없으면 적절한 안내를 제공한다.

### M07. 정책 상세정보 및 신청 준비 안내

- 우선순위: Must
- 주 담당: 김하정 (백엔드)
- 협업: 윤정찬 (DB), 탁서윤 (AI), 이현서 (프론트엔드)

#### 기능 설명

추천 정책의 상세정보와 신청 준비사항을
공식 정책자료에 근거하여 안내한다.

#### 입력

- 사용자가 선택한 정책 ID
- 해당 정책의 상세정보
- 사용자 자격 진단 결과

#### 처리

1. 정책 ID를 기준으로 상세정보를 조회한다.
2. 정책의 지원 내용과 주요 자격 조건을 표시한다.
3. 공식 자료에 명시된 신청기간과 신청 방법을 안내한다.
4. 확인된 준비서류 및 추가 확인사항을 제공한다.
5. 공식 신청 페이지 또는 안내 페이지로 연결한다.
6. 확인되지 않은 정보는 임의로 생성하지 않는다.

#### 출력

- 정책명 및 운영 기관
- 지원 내용
- 주요 자격 조건
- 신청기간 및 신청 방법
- 확인된 준비서류

## 5. 공통 품질 및 안전 요구사항

### 5.1 AI 응답

- AI 생성 콘텐츠임을 화면에 명시한다.
- 최종 수급 자격을 확정하지 않는다.
- 공식 출처가 없는 정책정보를 생성하지 않는다.
- 검색 결과가 없을 때 정책을 임의로 추천하지 않는다.
- 조건이 불명확하면 '추가 확인 필요'로 표시한다.

### 5.2 개인정보 보호

- 회원가입 없이 기본 기능 이용을 목표로 한다.
- 부모님 소득·재산 정보는 필요한 경우에만 입력받는다.
- 주민등록번호 등 고유식별정보는 수집하지 않는다.
- 불필요한 사용자 입력과 개인정보를 저장하지 않는다.
- 외부 AI 서비스에 전달하는 정보를 최소화한다.
- 개인정보 처리 사실과 목적을 이용자에게 안내한다.

### 5.3 정책 데이터 품질

- 공식 기관의 정책정보를 우선 사용한다.
- 정책마다 공식 출처 URL을 저장한다.
- 마지막 확인일을 기록한다.
- 신청기간과 모집상태가 불명확하면 확인 필요로 표시한다.
- 중복 수혜 관련 조건은 공식 근거가 있을 때만 판단한다.

### 5.4 서비스 안정성

- API 요청 실패 시 오류 메시지를 제공한다.
- 데이터 조회 실패 시 재시도 방법을 안내한다.
- AI 응답이 지연되면 로딩 상태를 표시한다.
- 핵심 기능은 PC와 모바일에서 이용할 수 있어야 한다.

### 6.3 대표 통합 테스트 시나리오

#### 시나리오 A. 정상 추천 흐름

입력:
"나는 25살이고 창원에서 자취 중인 취준생이야.
월세가 부담돼."

기대 결과:

1. 나이 25세, 창원시, 취업준비생, 주거비 관심 추출
2. 입력되지 않은 소득·가구 정보는 미입력 처리
3. 주거 관련 공식 청년정책 검색
4. 정책별 자격 조건 진단
5. 관련 정책이 여러 개면 함께 추천
6. 추천 근거와 공식 출처 표시
7. 신청 준비사항 안내

#### 시나리오 B. 자격 조건 미충족

입력:
"나는 40살이고 창원에 살고 있어.
청년 월세 지원을 알아보고 싶어."

기대 결과:

1. 나이 40세 추출
2. 해당 정책의 공식 연령 조건과 비교
3. 연령 기준을 벗어난 정책은 미충족 표시
4. 미충족 정책을 적합한 혜택으로 추천하지 않음

※ 특정 정책의 연령 기준은 실제 공고를 따른다.

#### 시나리오 C. 부모님 경제정보 부족

입력:
"나는 23살 대학생이고 부모님과 따로 살고 있어.
부모님 재산은 잘 모르겠어."

기대 결과:

1. 나이, 학생 상태, 거주 상황 추출
2. 부모님 재산은 미확인 처리
3. 원가구 조건이 필요한 정책을 검색한 경우
   해당 조건을 추가 확인 필요로 표시
4. 임의로 충족 또는 미충족으로 판단하지 않음

#### 시나리오 D. 여러 혜택 추천

입력:
"나는 26살이고 창원에 사는 취준생이야.
월세와 생활비 지원을 함께 알아보고 싶어."

기대 결과:

1. 주거·생활 분야의 관련 정책 검색
2. 정책별 자격 조건 진단
3. 관련 정책을 최대 5개까지 함께 표시
4. 정책별 추천 이유 제공
5. 중복 수혜 가능성을 근거 없이 확정하지 않음

4. 완료한 작업은 Pull Request로 제출한다.
5. PR에는 변경 내용과 테스트 결과를 작성한다.
6. 다른 팀원의 검토 후 main에 병합한다.
7. main 브랜치에는 정상 동작하는 코드를 유지한다.
8. API 키, 비밀번호, 개인정보는 업로드하지 않는다.

### 7.5 기능 연동 협의 사항

개발 시작 전 다음 항목을 협의한다.

- 프론트엔드와 백엔드의 요청·응답 JSON 형식
- 자연어 조건 추출 결과의 필드명 및 자료형
- 정책 및 자격 조건 DB 구조
- RAG 검색 결과의 정책 ID 및 근거 연결 방식
- AI Agent와 백엔드 Tool 호출 인터페이스
- 자격 진단 상태값 및 오류 응답 형식

각 영역의 데이터 형식은 협의하여 통일하고,
변경이 필요한 경우 관련 팀원에게 공유한다.

### 7.6 조장의 통합 및 검증 업무

조장은 각 기능이 독립적으로 동작하는지 확인하고,
전체 사용자 흐름에서 정상적으로 연결되는지 검증한다.

주요 작업:

1. 기능별 개발 진행 상황 확인
2. 프론트엔드·백엔드·AI·DB 연결 테스트
3. Must 기능 테스트 케이스 실행 및 결과 관리
4. API 오류와 데이터 불일치 문제 조정
5. 배포 환경 점검
6. 평가자 테스트 절차 및 제출물 확인

### 7.7 팀원별 기여 기록

각 팀원은 담당 업무의 실제 결과물을 GitHub에 남긴다.

- 담당 GitHub Issue
- 기능 개발 및 수정 커밋
- Pull Request
- 테스트 코드 또는 테스트 결과
- 기술 문서 및 데이터 검증 기록

기여도는 단순 커밋 개수보다
실제 작업 내용과 결과를 중심으로 관리한다.

## 8. 요구사항 보완 및 검토 사항

### 8.1 부모님 경제정보 입력

부모님 소득·재산 정보는 해당 정책에서
요구하는 경우에만 선택적으로 입력받는다.

입력 정보가 없거나 정확성이 확인되지 않은 경우
자격을 임의로 확정하지 않고
'추가 확인 필요'로 표시한다.

### 8.2 RAG 동작 검증

RAG는 단순 정책 목록 조회에 그치지 않고,
검색된 정책 근거 문서를 AI 답변에 활용해야 한다.

추가 테스트:
- TC-M03-04
- 내용: 정책 근거 문서 검색 후 AI 답변 생성
- 기대 결과: 검색된 근거와 답변 내용이 일치하며
  공식 출처가 표시된다.

### 8.3 복수 혜택 추천 안전장치

혜택 포트폴리오에 여러 정책이 표시되더라도
모든 정책을 동시에 수급할 수 있다는 의미는 아니다.

중복 수혜 가능성이 공식적으로 확인되지 않았다면
이를 확정적으로 표현하지 않는다.

### 8.4 평가자 테스트 환경

평가자가 별도의 개발 환경이나 관리자 계정 없이
배포된 웹서비스에서 핵심 기능을 이용할 수 있도록 한다.

README에 테스트용 자연어 입력 예시와
정상 결과 확인 방법을 작성한다.
