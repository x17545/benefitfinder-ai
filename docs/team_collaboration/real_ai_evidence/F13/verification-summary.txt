2026-11-21 로컬 통합 검증

• 격리된 로컬 PostgreSQL 17.11에 가상 조항을 넣고 실제 추천 API 요청을 한 번 보냈습니다. 테스트 DB의 추천 조항 조회는 SELECT 권한만 있는 역할로 실행했습니다. 이 검증은 운영 DB와 연결하지 않았으며 실행 후 테스트 클러스터를 종료했습니다.
• local-request-trace.jsonl의 요청 ID f13-test-0d307c022ac44a7e와 조회 ID S1를 따라 4~8번 이벤트를 확인할 수 있습니다. PostgreSQL 서버 로그에서 SELECT 실행을 확인했고, 반환된 가상 조항 2건의 ID·제목·본문 목록이 Ollama에 실제로 전송한 프롬프트의 clauses와 일치했습니다. 두 이벤트는 같은 SHA-256을 기록합니다.
• gemma4:e4b가 “임대차계약서와 월세 납부 확인서를 제출해요.”를 생성했습니다. 생성 문장과 DB 조항에 일치하는 인용이 최종 HTTP 200 응답에 포함됐으며, ai_generated=true와 출처 1건을 확인했습니다. 로그에는 원문·프롬프트 전문·프로필·접속 정보를 남기지 않았습니다.

2026-11-07~08 기존 검증 및 가상 사례 캡처

• 2026-11-07 추천 API 통합 검증. 가상 정책·조항·프로필로 실제 POST /api/v1/recommendations 요청을 보냈습니다. PostgreSQL 17.11에서 가상 조항을 읽고 로컬 Ollama의 gemma4:e4b로 설명을 생성했습니다. HTTP 200, 4.397초였으며, 결과에 표시한 두 정책 모두 ai_generated=true, ai_sources는 정책별 1건이었습니다. 같은 입력으로 테스트 DB를 중지하자 두 정책 모두 ai_generated=false와 빈 ai_sources를 반환했고 계산 결과는 유지됐습니다.
• 가상 사례의 AI 설명에는 “임대차계약서와 월세 납부 자료를 제출해요.”가 표시됐습니다. 첨부한 f13-synthetic-result.jpg는 당시 결과 화면입니다.
• 2026-11-08에는 실제 공고에서 사람이 승인한 조항으로 별도의 로컬 미게시 검증을 했습니다. 가상 프로필로 보낸 요청 4건 모두 실제 PostgreSQL 조회와 gemma4:e4b 설명 생성을 거쳐 HTTP 200, ai_generated=true, 응답별 출처 1건을 반환했습니다. 네 응답은 각각 2.453초, 1.389초, 1.301초, 1.308초였습니다.
• 당시 코드에서 검색된 조항의 ID·제목·본문을 모델 요청의 clauses에 넣고, 출력 인용이 해당 조항의 본문에 포함되는지 확인하는 경로를 확인했습니다. 성공 응답과 DB 중지 시 기본 안내는 저장본에서 대조했습니다. 해당 요청과 직접 대조할 수 있는 SQL 로그와 전송 프롬프트 원본은 확보하지 못했습니다.
