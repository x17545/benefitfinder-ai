# 배포 사이트 점검 기록

배포된 웹사이트에서 사용자 흐름을 확인하고 정상 동작, 오류, 미확인을 나눠 적는다. 개선 의견은 아직 반영되지 않은 제안이다. 화면 번호와 문구 ID는 [기능 명세](REQUIREMENTS.md) 4장을 따른다. 6장에 기획서·명세서의 기능 목록과 실제 구현을 비교했고, 7장에 문구·화면 흐름 개선안, 8장에 사용자 테스트 준비 점검을 적었다.

1장부터 6장까지는 점검한 날의 기록이다. 증빙으로 남기기 위해 이후에 바뀐 내용으로 고쳐 쓰지 않는다. 점검 이후 바뀐 상태는 바로 아래 '현재 상태'에 따로 적는다.

## 3. 오류와 확인이 필요한 점

### 3.1 1차 점검 오류 (해결됨)

- [내 조합 찾기]를 누르면 진행 단계 표시 없이 바로 실패 화면(문구 L-E1 "지금은 정책 자료를 불러올 수 없어요")이 나왔다. [다시 시도]도 같았다.
- 같은 시각 백엔드 `/health`는 200이었다. 원인은 실제 정책 DB 연동 진행 중으로 안내받았다.
- 2차 점검에서 같은 조건으로 분석이 끝까지 진행됐다. 이 오류는 해결된 것으로 본다.

### 3.2 2차 점검에서 확인이 필요한 점

담당자 확인 전 관찰이다. 원인을 단정하지 않는다.

## 7. 문구·화면 흐름 개선안 (2026-11-19 팀장 요청)

팀장이 11-19 기획에 요청한 두 가지(자격 조건 충족·확인 필요 안내 문구 검토, 정책 상세 설명·신청 링크·화면 이동 흐름 개선안)를 3차 점검 결과로 정리했다. 모두 아직 반영되지 않은 제안이다. 문구를 확정하면 [기능 명세](REQUIREMENTS.md) 4.10 문구 목록과 11.5 변경 이력에 반영한다.

### 7.1 왜 내부 코드가 보이는가 (담당자 참고)

- 화면은 조건 이름표에 없는 `condition_id`를 받으면 그 이름을 그대로 보여 준다 (`apps/web/src/domains/youth/conditionLabels.ts`의 `conditionLabel`). 이름표에는 나이·지역 등 12개만 있다.
- 공고 원문 기반으로 게시한 현금 정책은 원문 전체를 2,400자씩 잘라 `official_source_terms_0`, `_1` … 조건을 만들고 모두 수동 확인(`manual`)으로 둔다 (`backend/src/benefitfinder/ingestion/source_cash.py`). 그래서 칩이 여러 개 생기고, 근거 칸에 원문 덩어리와 `chars:0-2400` 위치가 나오고, 나이처럼 코드로 판정할 수 있는 조건도 '확인 필요'가 된다 (3.3 H·Q·R, 팀장이 공유한 '만 25세인데 만 18세부터 34세 대상 정책의 나이가 확인 필요' 사례).
- S6 서비스 카탈로그의 `youth-audience-manual`, `eligibility:1` 같은 이름도 같은 이유로 그대로 보인다.

### 7.2 자격 진단 안내 문구

원칙은 세 가지다.

1. 영어 내부 이름은 어떤 경우에도 화면에 보이지 않는다. 이름표에 없는 조건은 '공고 조건'으로 보여 준다.
2. '확인 필요'는 사용자가 할 일로 쓴다. '입력 정보나 기준 적용을 확인해야 해요'처럼 누가 무엇을 확인하는지 모르는 문장은 쓰지 않는다.
3. 같은 종류의 확인 필요 조건은 칩 하나로 묶는다. 원문 덩어리 조건이 몇 개든 칩은 '공고 조건' 하나다.

### 7.4 조건 고르기 아래 표시 (제안 2 구체안)

### 8.3 테스터에게 함께 보낼 안내

설문 링크와 함께 아래 내용을 보낸다.

- 결과 금액은 참고용이고, 실제로 받을 수 있는지는 신청 기관에서 확인해야 한다.
- '? 확인 필요'는 서비스가 입력한 조건만으로 판단하지 못한 조건이다. 틀렸다는 뜻이 아니다.
- 사는 지역에 따라 결과가 1개만 나오거나 적게 나올 수 있다. 지금은 취업·주거 지원만 다룬다.
- 실제 소득·재산을 고르기 싫으면 비슷한 구간을 골라도 된다. 고른 조건은 서버에 저장하지 않는다.
- 이상한 화면이 보이면 캡처해서 설문 마지막 칸에 적어 달라.

테스트를 시작하기 전에 팀이 정해야 할 것은 세 가지다.

1. 3.3 H(영어 이름)·K(총액)·Q(원문 덩어리)를 테스트 전에 고칠지, 알려진 문제로 두고 진행할지
2. 상황 탭을 누를 때마다 분석 횟수가 줄어드는 것(3.3 P). 테스터 여러 명이 같은 날 쓰면 하루 100회가 모자랄 수 있다
3. 부탁 5·9·10을 이번 테스트에서 보류로 둘지
