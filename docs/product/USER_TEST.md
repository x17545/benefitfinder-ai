# 사용자 테스트 진행안과 설문

> 목적: docs/product/REQUIREMENTS.md 8.6 성공 기준 중 이해도와 만족도, 입력 시간을 확인하고, 고칠 곳을 찾는다.
> 현행 기준: [docs/product/REQUIREMENTS.md](REQUIREMENTS.md) v3.0, 기획서 [PROJECT_PLAN.md](PROJECT_PLAN.md), 구글 폼 설문 기록 [USER_TEST_SURVEY.md](USER_TEST_SURVEY.md)
> 평가 기준 G5(실사용자 5명 이상 피드백)와 G7(테스터 이름·연락처 비공개)의 제출 기록을 이 문서에 남긴다. 기록할 곳은 5장(참여자)과 6장(피드백과 반영)이다.
> 취업·주거 혜택에 F01~F14와 13단계를 적용해 평가한다. 다른 분류는 확장 대상으로 분리하고 MVP 실패로 세지 않는다.

## 1. 진행 방법

| 항목 | 내용 |
|---|---|
| 대상 | 서비스 타깃(만 19세부터 39세, 취업 준비·대학생·사회초년생 등 취업·주거 지원이 필요한 청년)에 해당하는 실사용자 **5명 이상**. 빠지는 사람을 생각해 6명부터 7명을 모집한다. 가능하면 취업 준비, 재직, 기혼, 35세 이상이 섞이게 |
| 제외 | **팀원은 실사용자로 세지 않는다.** 다른 팀 교육생은 서비스 타깃에 해당할 때만 인정되므로 5장에 타깃 해당 근거를 꼭 적는다 |
| 방식 | 배포된 주소로 본인 휴대폰에서 직접 사용. 진행자는 옆에서 보기만 하고 돕지 않는다 |
| 시간 | 1명당 15분 (사용 5분부터 10분, 설문 5분) |
| 준비물 | 배포 주소, 아래 관찰 기록표, 설문 링크(구글 폼) |
| 진행자 | 현서 (기록 1명 더 있으면 좋음) |

**실제 진행 방식 (2026-11-20~23)**

위 표와 관찰 기록표는 초기 대면 테스트 계획이다. 실제 사용자 테스트는 배포된 Vercel 서비스에 접속한 뒤 구글 폼에 응답하는 비대면 방식으로 진행했다. PC와 모바일 모두 허용했으며 진행자가 직접 관찰하거나 시간을 측정하지 않았다.

조건 입력 시간과 결과 표시 여부는 설문 24·25번의 자기보고 응답으로 집계했다. 기기는 26번으로 확인했다. 실제 진행 절차와 설문 문항은 [사용자 테스트 설문조사](USER_TEST_SURVEY.md)를 따르며, 최종 집계와 참여자 기록은 4·5장을 참고한다.

**참여 동의 (시작 전에 받는다)**

> 테스트 결과는 팀 GitHub 저장소에 기록되지만 이름과 연락처는 올리지 않고 T1, T2 같은 가명으로만 적어요. 사용하면서 한 말과 설문 응답은 서비스 개선과 과제 제출에 쓰여요. 결과 화면의 [AI] 표시가 붙은 설명은 AI가 공고 원문을 보고 쓴 거예요. 동의하시나요?

동의 여부는 설문 번호를 매기지 않는 사전 필수 체크로 받는다. 지표에 쓰는 설문 1번·11번 번호는 바꾸지 않는다. 이름·연락처는 사례 연락용으로만 진행자가 따로 보관하고 저장소에는 올리지 않으며, 과정이 끝나면 지운다.

**시작할 때 읽어 주는 말**

> 이 서비스는 받을 수 있는 청년 취업·주거 지원금을 조합해서 보여 주는 서비스예요. 서비스를 평가하는 거라 편하게 진행해 주세요. 실제 소득이나 재산을 고르기 싫으면 비슷한 값을 골라도 괜찮아요. 고른 조건은 저희가 따로 기록하지 않아요.

**기억하기 선택 시 덧붙이는 말**

> 입력 중인 조건과 마지막 결과는 기억하기를 꺼도 지금 탭에 임시로 남아요. 기억하기를 켜고 분석을 시작하면 조건을 이 브라우저에 추가로 30일 저장하고, 만료 뒤 다음 접속 때 지워요. 서버에는 저장되지 않아요. 저희 관찰 기록과 브라우저 저장은 분리되어 있어요. 관찰 기록에는 조건 값을 적지 않아요. 끝나고 지우기를 누르면 브라우저 저장값이 바로 지워져요.

**부탁할 일 (순서대로)**

대상 앱 URL/커밋과 실제 앱·클릭 시안 중 어느 것을 테스트하는지 먼저 기록한다. 시안은 화면 흐름만 확인하며 서버 전송·30일 저장·이미지 다운로드·실제 AI 생성·운영 갱신이 없다. 목표 기능의 성공은 실제 앱에서만 기록한다.

1. 시작 화면에서 기억하기 선택 여부를 정한 뒤 처음부터 조건을 골라 결과까지 가 보기 (F01, F03). 실제 앱은 분석 후 탭을 닫고 다시 열어 기억하기를 확인한다
2. 결과 화면에서 왜 이 조합이 1위인지 말로 설명해 보기 (F05)
3. 기간을 2년으로 바꾸고 무엇이 달라졌는지 말해 보기 (F05)
4. 현재가치로 보기를 켜 보고 무슨 뜻인지 말해 보기 (F05)
5. 상황이 바뀌면에서 연 소득이 오르면을 눌러 보고 무슨 뜻인지 말해 보기 (F06)
6. 관심 가는 정책 하나의 신청 페이지까지 가 보기 (F07)
7. 조건 수정으로 값을 바꾸고 결과가 다시 계산되는지 보기 (F01, F04)
8. 결과 이미지 저장을 눌러 실제 PNG와 입력 조건 미포함을 확인하기 (F10). 클릭 시안은 토스트만 있으며 파일 저장 성공으로 기록하지 않는다
9. 조건 입력 후 결과 목록 또는 상세에서 [AI] 설명을 읽고, 무슨 내용인지와 누가 쓴 설명인지 말해 보기 (F13). 기본 문구에는 AI 표시가 없어야 하며 시안의 고정 예시는 실제 생성 성공으로 기록하지 않는다
10. [돈 말고 받을 수 있는 도움]에 들어가서 '약 ○만 원'이 무슨 뜻인지 말해 보기 (F14)

관심 선택·검색·결과·상황 변화·상세에 취업·주거만 나오는지 확인한다. 가상 계산은 현행 8.3과 `tests/fixtures/mvp_planning_rules.json`을 사용하고 과거 5정책 예시·PNG의 숫자를 수락 기준으로 삼지 않는다. 실제 정책의 확보 수와 정확성은 별도 검수한다.

매일 자동 갱신(F08)과 배포, 사용 상한, 이용 통계(F11)는 테스트 당일 환경 전제로 확인한다. 확인 항목은 4장 결과 정리 양식에 둔다.

## 2. 관찰 기록표 (진행자가 작성)

## 3. 설문 (구글 폼, 사용 직후)

5점 문항: 1 전혀 아니다, 2 아니다, 3 보통, 4 그렇다, 5 매우 그렇다

**A. 이해와 신뢰**

1. 추천 조합이 왜 1위인지 이해됐다
2. 포기하는 지원금이 무슨 뜻인지 이해됐다
3. 현재가치로 보기가 무슨 뜻인지 이해됐다
4. 상황이 바뀌면 화면이 내 상황을 판단하는 데 도움이 됐다
5. 충족과 미충족, 확인 필요 표시가 이해하기 쉬웠다
6. 결과를 믿을 수 있다고 느꼈다 (출처, 근거 문장)

**B. 사용 편의**

7. 질문 수가 적당했다
8. 질문이 이해하기 쉬웠다
9. 분석을 기다리는 시간이 괜찮았다
10. 화면이 보기 편했다

**C. 가치**

11. 온통청년과 보조금24 같은 다른 서비스보다 도움이 됐다
12. 실제로 지원금을 신청할 때 다시 쓰고 싶다
13. 친구에게 추천하고 싶다

**D. 주관식**

14. 가장 좋았던 점
15. 가장 헷갈리거나 불편했던 점
16. 질문 중 대답하기 싫었거나 어려웠던 것 (단계 이름)
17. 이런 기능이 있으면 좋겠다

**E. 기본 정보 (선택)**

18. 나이대: 19부터 24, 25부터 29, 30부터 34, 35부터 39
19. 지금 상황: 학생, 취업 준비, 재직, 기타
20. 정부 지원금을 신청해 본 적: 있다, 없다

**F. AI 설명과 돈 말고 받을 수 있는 도움 (v3.0 추가)**

21. [AI] 표시가 붙은 설명이 내 상황을 이해하는 데 도움이 됐다
22. AI 설명을 믿을 수 있다고 느꼈다 (근거 조항 표시)
23. '돈 말고 받을 수 있는 도움' 화면의 환산 금액이 도움이 됐다

설문 맨 앞에 번호 없는 참여 동의(필수 체크)를 둔다. 이해도 문항은 기존 설문 1번이다. 구글 폼에 이름·연락처 문항을 만들지 않는다. 문항 번호는 기존 기준(8.6의 설문 1번·11번)을 유지하려고 F 묶음을 21번부터 붙였다.

## 4. 결과 정리 양식

| 지표 (docs/product/REQUIREMENTS.md 8.6) | 목표 | 결과 | 통과 |
|---|---|---|---|
| 이해도: 설문 1번 그렇다 이상 비율 | 80퍼센트 이상 | 75.0퍼센트 (화면을 본 48명 중 36명) | 미달 |
| 만족도: 설문 11번 평균 (온통청년·보조금24 같은 다른 서비스보다 도움이 됐는지) | 4점 이상 | 3.83점 (53명) | 미달 |
| 조건 입력 시간 중간값 | 3분 이하 | 1~2분 구간 (53명 중 47명이 3분 이내) | 통과 |
| 실사용자 수 (팀원 제외, 타깃 근거 있음) | 5명 이상 (G5) | 49명 (아래 집계 근거) | 통과 |
| 신청 페이지 도달 (부탁 6) | 참고 | 설문 문항에 없어 측정하지 않음 | 미측정 |
| AI 설명 이해: 설문 21번 그렇다 이상 비율 | 참고 | 81.6퍼센트 (화면을 본 49명 중 40명) | 참고 |
| 환경 전제: 매일 자동 갱신 시각과 기준금리 표시 확인 (F08) | 참고 | 설문으로 확인하지 않음 | 미측정 |
| 환경 전제: 배포 주소 전체 흐름 동작 (F11) | 참고 | 설문 25번: 나왔어요 35명, 받을 수 있는 조합이 없다고 나왔어요 6명, 잘 모르겠어요 10명, 오류 화면이 나왔어요 2명 | 참고 |

- 만족도는 REQUIREMENTS.md 8.6 기준대로 설문 11번 하나로 잰다. 11번은 서비스 전체 만족이 아니라 '온통청년·보조금24 같은 다른 서비스와 비교해 도움이 된 정도'를 묻는 문항이다.
- 실사용자 수 집계 근거: 구글 폼 응답 53명 중 팀원은 0명이다. 설문 링크는 팀원이 아닌 지인에게만 보냈고 팀원은 응답하지 않았다. 이 중 타깃 근거(19번 지금 상황과 18번 나이대 19~34세)를 모두 답한 49명을 실사용자로 셌다. 상황만 답한 1명과 둘 다 답하지 않은 3명은 응답 집계에는 넣고 실사용자 수에서는 뺐다. 사람별 근거는 5장 T1~T53에 있다.

금융값과 최종 자격 확인 안내: 화면 금액은 검수된 정책 데이터와 계산식으로 다시 확인한다. 금액이 검수 전 정책에서 왔거나 근거가 없으면 결과에 그 상태를 표시한다. 최종 자격은 참고 결과로만 안내하고, 신청 기관 확인 문구를 빠뜨리지 않는다.

## 6. 피드백과 반영 기록 (제출용)

개선 의견이 담긴 자유 응답 31건만 옮겼다('없음', 칭찬만 있는 응답은 4.1 요약에 반영). 응답은 고치지 않고 그대로 옮겼고, 실제 조건 값이 드러나는 부분만 [ ]로 생략했다. 같은 문제끼리 묶어 4장 고칠 것 목록과 순서를 맞췄다. 반영 여부는 실제 담당자의 작업 결과와 배포 화면·코드 검증을 근거로 기록했다. 개선 의견 31건 모두에 검토 상태와 확인 근거 또는 남은 사항을 기록했으며, 모든 의견의 완전한 해결을 뜻하지 않는다.

한 사람이 여러 의견을 냈으면 줄을 나눈다. 반영했으면 근거로 **커밋 또는 PR 링크와 바뀌기 전·후 화면**을 남기고, 반영하지 않았으면 **이유**를 적는다.

주요 개선 작업은 [PR #111](https://github.com/x17545/benefitfinder-ai/pull/111)에 반영됐다. 실제 배포 화면과 코드의 확인 결과는 [사용자 피드백 검증 보고서](../team_collaboration/USER_FEEDBACK_VERIFICATION.md)를 참고한다. 현재 확보된 화면 증빙은 개선 이후의 가상 재현 화면이며, 모든 항목의 개선 전·후 화면이 확보됐다는 의미는 아니다.

현재 증빙 폴더에는 2026-11-23 피드백 반영 및 배포 검증에 사용한 재현 화면 8개가 등록돼 있다. 실제 참여자의 화면이나 응답 원본을 공개한 것이 아니며, 개선 전 화면이 모두 확보됐다고 주장하지 않는다.

**검증 범위 및 한계**

- 실제 배포 서비스의 대표 화면과 일부 상호작용 및 관련 코드를 확인했다.
- 상황 변화의 실제 운영 오류와 사용량 초과 상황은 재현하지 않았다.
- 개별 정책 신청 화면 직접 연결 및 전체 정책의 자격 판정 정확성은 별도 검증 대상이다.
- 개선 후 재설문은 실시하지 않았다. 이해도 75.0%, 다른 서비스 대비 도움 정도 3.83점, 입력 시간 중간값 1~2분은 기존 설문 결과이며 개선 이후의 측정값이 아니다.

**응답 원본**

- 구글 폼 응답 원본·CSV와 편집 중인 사본은 로컬 Git 제외 `data/`에만 보관한다. 이름·연락처·이메일·시각 열을 지운 것만으로 비식별됐다고 보지 않는다. 자유 응답·화면에 남은 나이·지역·소득·재산·특수 조건·부모님 정보와 식별 가능한 발언도 제거한다. 원본 CSV를 저장소에 올리지 않는다.
- 공유할 때는 5·6장의 가명과 실제 확인한 집계·개선 요약만 남긴다. 아직 진행하지 않은 참여자·동의·팀원 아님 확인·성공 여부는 미기입으로 둔다.
- 올리기 전에 한 사람이 더 열어 보고 개인정보가 남았는지 확인한다.
