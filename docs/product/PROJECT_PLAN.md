## 한눈에 보기

> 청년이 13단계 선택지로 자기 조건을 고르면, **함께 받을 수 있는 취업·주거 지원금 조합 중 총액이 가장 큰 것**을 계산해 보여 준다.
> AI는 정책 원문을 읽고 조건을 뽑아내고(AI Agent), 결과마다 원문을 근거로 쉬운 설명을 쓴다(RAG). 이 과정은 매일 새벽 자동으로 갱신된다(자동화).
> 금액과 자격 판정은 AI가 아니라 코드가 계산한다.


## 1. 문제 정의

### 1.1 청년이 겪는 어려움

취업·주거 지원 정책은 많지만, 정책을 **찾은 뒤에도** 청년이 직접 판단해야 할 것이 많다.

| 사용자가 직접 해야 하는 일 | 그래서 생기는 문제 |
| --- | --- |
| 여러 기관 공고를 하나씩 찾아 읽기 | 받을 수 있는 정책을 모르고 지나침 |
| 나이·소득·주거 조건을 내 상황과 하나씩 맞춰 보기 | 확인 안 된 조건을 '될 것 같다'고 오해 |
| "다른 사업과 함께 받을 수 없음" 같은 조항을 정책끼리 비교하기 | 함께 못 받는 지원금을 둘 다 받을 수 있다고 착각 |
| 매달 주는 돈, 한 번에 주는 돈, 만기에 주는 돈을 같은 기준으로 비교하기 | 금액이 커 보이는 정책 하나를 고르다 더 큰 조합을 놓침 |
| 취업하거나 소득이 오를 때 무엇이 끊기는지 다시 계산하기 | 소득은 조금 늘었는데 지원금이 더 크게 끊겨 손해 |
| 정장 대여·상담 같은 지원이 얼마짜리인지 가늠하기 | 돈이 아니라는 이유로 가치 있는 지원을 지나침 |

### 1.2 핵심 문제

**청년은 자기 조건에 맞는 정책을 찾은 뒤에도, 함께 받을 수 있는 것 중 어떤 조합이 가장 이득인지, 상황이 바뀌면 어떻게 달라지는지 스스로 계산해야 한다.**

기존 정책 검색 서비스는 '받을 수 있는 정책 목록'을 보여 주는 데서 멈춘다. 이 서비스는 그다음 단계인 **조합 선택과 비교**를 돕는다.

이 문제 정의는 팀의 가설이며, 실사용자 테스트(5명 이상)에서 실제로 어디서 막히는지 확인한다.

## 3. 해결 방법

### 3.1 사용 흐름

1. **조건 고르기**: 나이, 지역, 상황, 주거, 소득 등을 13단계 선택지로 고른다 (약 3분). 문장을 쓰거나 AI에게 질문하지 않는다.
2. **조합 비교**: 함께 받을 수 있는 지원금 조합 최대 3개를 총액순으로 본다. 기간(1년·2년·전체)과 '현재가치로 보기'를 바꿔 볼 수 있다.
3. **이유 확인**: 지원금마다 ✓ 충족 / ✕ 미충족 / ? 확인 필요와 원문 근거, AI가 쓴 맞춤 설명을 본다. 이 조합을 고르면 포기하는 지원금도 보여 준다.
4. **상황 바꿔 보기**: 취업하면, 소득이 오르면, 독립하면 조합과 총액이 어떻게 바뀌는지 본다.
5. **돈이 아닌 지원 보기**: 정장 대여 같은 서비스를 '돈으로 치면 약 ○원'으로 따로 본다.
6. **신청하러 가기**: 공식 신청 페이지로 바로 연결된다.

### 3.2 핵심 기능

모든 기능은 Must(반드시 구현)다. 자세한 규칙은 명세서 3장과 5장에 있다.

| 기능 | 하는 일 |
| --- | --- |
| 조건 선택 입력 (F01) | 13단계 선택지, 확인·수정 |
| 정책 검색 (F02) · 분석 진행 표시 (F03) | 조건에 맞는 정책 후보를 찾고, 진행 상황을 화면에 실시간 표시 |
| 자격 진단 (F04) | 조건별 충족·미충족·확인 필요와 원문 인용 |
| 최적 조합 (F05) | 함께 못 받는 정책을 빼고 총액이 큰 조합 3개, 포기하는 지원금, 현재가치 |
| 상황 변화 분석 (F06) | 취업·소득 증가·독립 때 조합 변화, 소득이 올라도 오히려 손해인 구간 경고 |
| 정책 상세·신청 안내 (F07) | 신청 기간·방법·서류·공식 링크 |
| 매일 자동 갱신 (F08) | 매일 새벽 3시 정책 다시 모으기, 디스코드 보고 |
| 기억하기 (F09) · 결과 이미지 저장 (F10) | 조건을 내 브라우저에만 30일 저장, 결과를 그림으로 저장 |
| 배포·통합 (F11) | 외부 접속, 하루 사용 상한 |
| 정책 원문 분석 Agent (F12) | AI가 원문에서 조건·금액·중복 제한·서비스 내용을 뽑음 |
| 맞춤 설명 (F13) | AI가 원문 조항을 찾아 '왜 나에게 맞는지·지금 할 일'을 씀 |
| 지원금이 아닌 서비스 (F14) | 정장 대여 등 서비스를 환산 금액과 함께 별도 화면에 표시 |

### 3.3 범위

| 하는 것 | 하지 않는 것 |
| --- | --- |
| 청년 **취업·주거** 정책 (먼저 이 두 분야에 집중) | 생활·자산형성·교육 등 다른 분야 (나중에 확장) |
| 온통청년·보조금24 공공 API로 수집 | 크롤링은 하지 않음. 공공 API로 충분하다고 판단 |
| 공식 신청 페이지로 연결 | **지원금 서류 대리 제출** |
| 결과와 함께 AI 맞춤 설명 한 번 제공 | **질의응답** (사용자가 묻고 AI가 답하는 기능), 챗봇 |
| 돈이 아닌 서비스를 환산 금액으로 따로 표시 | 환산 금액을 현금 총액에 합치기 |
| 조건을 내 브라우저에만 저장 | 로그인, 서버에 사용자 정보 저장, 알림 |
| 참고용 계산 결과 | 최종 수급 자격 확정 |


## 4. AI 활용 방식

### 4.1 원칙: 숫자는 코드가, 글은 AI가

지원금 계산이 틀리면 사용자가 실제로 손해를 본다. 그래서 **자격 판정·금액·조합 순위는 코드가 계산**하고, AI는 사람이 하기 어려운 두 가지 일에 쓴다.

1. 길고 복잡한 정책 원문을 읽고 조건을 정리하는 일
2. 계산 결과를 사용자 상황에 맞춰 쉬운 말로 설명하는 일

### 4.2 AI를 쓰는 곳 3가지

| 기술 요소 | 어디에 | 무엇을 하나 | 평가 기준(G3)과 맞춰 보기 |
| --- | --- | --- | --- |
| **AI Agent** | 정책 원문 분석 (F12) | AI가 원문을 읽으며 도구 6개(원문 가져오기, 조항 찾기, 규칙 뽑기, 다른 정책과 연결, 빠진 항목 검사, 저장) 중 지금 필요한 것을 스스로 골라 쓴다. 빠진 항목이 있으면 다시 찾는다 | 2개 이상의 도구 중 스스로 골라 호출, 여러 단계 반복 |
| **RAG** | 결과 화면 맞춤 설명 (F13) | 분석할 때마다 그 정책의 원문 조항을 DB에서 찾아 AI에게 넘기고, AI는 그 조항만 근거로 두세 문장을 쓴다 | 요청마다 DB를 검색해 결과를 프롬프트에 넣음 |
| **자동화 워크플로우** | 매일 자동 갱신 (F08) | 매일 새벽 3시, 공공 API 수집 → DB 저장 → AI Agent 분석 → 디스코드 보고가 사람 손 없이 이어진다 | 정해진 시각에 시작, 2개 이상 서비스가 사람 없이 연결 |

기준은 2개 이상이지만 3개를 쓴다. 하나가 인정받지 못해도 기준을 지킬 수 있게 하기 위해서다.

### 4.3 AI가 실수하지 않게 하는 장치

- AI가 뽑은 조건은 **사람이 검수한 뒤에만** 계산에 쓴다.
- AI 설명 속 숫자·정책 이름이 계산 결과와 다르면 그 설명을 버리고 정해진 문장으로 대신한다.
- 원문에 없는 내용은 쓰지 않는다. 근거 조항이 없으면 AI 설명을 만들지 않는다.
- AI가 쓴 설명에는 화면에 **[AI] 표시**를 붙인다.
- AI에게는 소득·재산 금액, 장애·수급 같은 민감한 조건, 부모님 정보를 보내지 않는다.


## 5. 기술적 접근

### 5.1 전체 구조

```
[매일 새벽 3시]  공공 API ─▶ DB ─▶ AI Agent 원문 분석 ─▶ 사람 검수 ─▶ 게시 · 디스코드 보고

[사용자]  화면 ─조건─▶ 서버: 정책 검색 → 자격 진단 → 조합 계산 → 원문 조항 검색 + AI 설명 ─▶ 화면
```

자세한 구조와 코드 위치는 명세서 12장(시스템 아키텍처)과 13장(AI 활용 명세)에 있다.

### 5.2 기술 스택과 선정 이유

| 영역 | 선택 | 고른 이유 |
| --- | --- | --- |
| 화면 | React + TypeScript + Vite | 조건 단계·조합 카드·진단 칩처럼 같은 모양이 반복되는 화면을 부품으로 나눠 만들기 좋다. TypeScript로 서버와 주고받는 데이터 형식 오류를 미리 잡는다 |
| 서버 | Python + FastAPI | 수집·AI·계산 코드를 모두 Python으로 쓸 수 있어 팀원끼리 코드를 공유하기 쉽다. 진행 상황 실시간 전송(SSE)과 자동 API 문서를 지원한다 |
| 데이터 검증 | Pydantic + JSON Schema | 화면과 서버가 같은 형식 약속(`contracts/v1`)을 쓰게 해서, 각자 개발해도 합칠 때 어긋나지 않는다 |
| DB | PostgreSQL | 정책·조건·출처·버전처럼 서로 연결된 데이터를 정확히 다룬다. RAG용 원문 조항 검색도 같은 DB 안에서 처리(pgvector 검토)해 DB를 하나로 유지한다 |
| AI | LLM API (모델은 비용 비교 후 회의 확정) | 원문 분석(F12)과 설명 생성(F13)에 쓴다. 도구 호출 기능이 있는 모델을 고른다 |
| 자동화 | 스케줄러 (GitHub Actions 또는 배포 서비스 크론, 회의 확정) + 디스코드 웹훅 | 서버를 계속 켜 두지 않아도 정해진 시각에 실행되고, 결과를 팀 채널에서 바로 본다 |
| 데이터 출처 | 온통청년 API, 공공데이터포털 보조금24 API, 한국은행 ECOS | 정부가 공식으로 제공하는 데이터라 출처를 밝힐 수 있다. 기준금리는 현재가치 계산에 쓴다 |
| 개발 도구 | uv(Python), pnpm(웹), GitHub Actions CI | 팀원 모두 같은 버전으로 설치·실행되게 잠금 파일을 쓴다 |
| 배포 | 미정 (Render 후보) | 외부 접속, 평가 결과 안내 전까지 유지 |

### 5.3 개인정보와 보안

- 회원가입 없이 쓴다. 조건은 서버에 저장하지 않고, '기억하기'를 켰을 때만 사용자 브라우저에 30일 저장한다.
- 시작 화면에서 필수 동의를 받고, 개인정보 처리방침에 받는 정보·저장 위치·AI로 보내는 정보를 적는다.
- API 키는 환경변수로만 관리하고 저장소에 올리지 않는다.
