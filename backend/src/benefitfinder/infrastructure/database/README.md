# PostgreSQL 어댑터

기본 DB는 PostgreSQL이다. 현재는 패키지 경계만 있으며 연결·테이블·ORM·드라이버·저장소 동작은 아직 없다.

윤정찬은 원천 데이터와 정제·검수 결과의 PostgreSQL 적재를, 양승현은 API·검색·계산에서 쓰는 조회·저장소 연동을 맡는다. 공용 연결·저장 모델·마이그레이션은 두 담당자가 함께 검토하고 파일별 변경을 조율한다. 탁서윤이 전달한 검수 결과·게시 버전을 보존하며 사용자 계산에는 게시 자료만 제공한다. 역할 분담과 무관하게 구체 DB 구현은 이 어댑터 경계에 둔다.

| 경로 | 책임 |
|---|---|
| 이 패키지 | DB 설정 해석, 연결 수명·트랜잭션 관리. 구현 시 필요한 파일부터 추가 |
| `models/` | PostgreSQL 저장용 모델과 테이블 매핑 |
| `repositories/` | application에 정의된 저장소 인터페이스의 PostgreSQL 구현 |

- API의 Pydantic 모델·순수 업무 모델·DB 모델을 구분한다. 자격 판정과 분야별 규칙은 DB 모델에 재구현하지 않는다.
- domain·application·AI·수집 모듈은 구체 DB 연결이나 저장소 클래스를 직접 import하지 않는다. 조립 지점이 저장소 인터페이스를 주입한다.
- 연결 수명과 트랜잭션은 어댑터에서 관리하고, 긴 LLM·수집 요청 동안 DB 트랜잭션을 열어두지 않는다.
- 설정은 백엔드 환경 변수로 받는다. 브라우저·공개 파일·로그에 연결 문자열을 노출하지 않는다.
- 스키마 변경은 `backend/migrations/versions/`에 이력으로 남긴다. import·서버 시작 시 자동 DDL을 수행하지 않는다.
- 저장소의 가상 구현은 단위 테스트에 사용할 수 있다. 실제 PostgreSQL 동작은 별도 테스트 DB에서 확인하며 SQLite 등으로 운영 DB를 임의 대체하지 않는다.
- pgvector는 미도입 선택 사항이다. 벡터 검색 필요성이 확인되기 전에는 확장이나 별도 벡터 DB를 전제하지 않는다.
